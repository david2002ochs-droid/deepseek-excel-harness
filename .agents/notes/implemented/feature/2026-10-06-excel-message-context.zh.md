# Agent Note: 小型 Excel 消息上下文与绑定的单元格引用

Status: implemented

[English](2026-10-06-excel-message-context.md) | 中文

## Problem

把 Harness UI 嵌入 Excel，并不会告诉智能体用户指的是哪个工作簿或选择范围。此前显示的选择标签，也可能与发送后续消息时的选择不同。单元格引用需要工作簿绑定，以免历史回答意外导航到另一窗格。

## Decision

[Excel 入口](../../../../excel/README.zh.md)让现有会话插件显式启用父框架 Office 桥接。每条普通消息在提交时、异步附件准备之前，开始新的元数据捕获。捕获的工作簿及工作表标识符、主机提供的工作簿名称与可用的文件定位信息、带工作表名称的选择地址以及观察时间，加入普通的持久用户消息文本。因此模型投影和重放保留相同输入，无需单独的会话事件格式或智能体循环修改。

上下文 JSON 限制为 2048 个 UTF-8 字节，另有固定标记与引用说明文本。包装层不读取单元格值、公式、VBA 或完整工作表清单。捕获失败或过大时，阻止消息接收并恢复草稿，不截断选择目标。独立 Web UI 不依赖此显式启用选项。

助手引用使用 `[[cite:Sheet1!A1:B2]]`，工作表名称遵循 Excel 引号规则。只有助手正文中的有界有效 A1 引用获得选择控件。代码示例、无效标记及没有匹配捕获元数据的回答保持文本。原回答提供其工作簿绑定，后续消息不能替换。父框架验证精确的子窗口、来源、请求标识符及窗格标识符，再次验证区域，然后激活工作表并选择区域，不写入单元格。

工作簿标识符仅属于任务窗格，重新加载或 Office 文档位置改变（包括另存为）时会改变。导航在选择之前再次检查位置。它并非原生 COM 句柄。Office 可能省略未保存工作簿的定位信息，此时绑定依赖 Office 将窗格保持在原文档中。后续 COM 操作必须自行解析并验证目标。此功能既不添加 COM 执行工具，也不配置模型路由。

## Alternatives considered

**复制现有 VBA 集成的完整准备扫描。** 其初始单元格、公式及 VBA 扫描超出所有者要求的小型定位信息包。智能体可稍后通过工具获取任务所需内容。

**为回答使用全局当前选择或工作簿。** 异步提交、引导消息及历史回答可能借用后来的选择或工作簿。每条消息的捕获及回答自身的引用绑定保留原目标。

**引入新会话事件或自定义外部链接协议。** 普通用户消息文本已提供持久的模型输入。单元格导航属于明确的 Excel 回调，外部链接委托则保留现有 URL 规则。

## Consequences

智能体获得小型、可重建的定位信息与准确选择引用，无需初始工作簿扫描。点击引用会改变活动工作表及选择区域；引用文本本身不能证明读取或修改了单元格。重新加载或不可用的绑定需要携带新上下文的新消息。

父框架测试覆盖仅读取元数据、大小限制、窗口与来源检查、重叠请求、释放及导航验证。客户端测试覆盖提交时序、失败恢复、持久消息重放、安全正文渲染及回答绑定。这些测试不能证明付费模型运行或原生 Office 验收，后两者需要独立证据。最终 Windows 安装包仍是单独的交付要求。
